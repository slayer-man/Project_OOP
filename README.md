Ядро для интернет-магазина (электронной торговли), построенное на основе объектно-ориентированного программирования (ООП) на Python. Текущий этап проекта посвящен **внедрению абстрактных классов (интерфейсов), использованию классов-миксинов для логирования через множественное наследование и расширению функционала (создание заказов)**.

## 🛠 Стек технологий
* **Язык разработки:** Python 3.14+
* **Менеджер зависимостей:** Poetry
* **Тестирование:** Pytest
* **Контроль покрытия тестами:** Pytest-cov
* **Форматирование кода:** Black
* **Проверка стиля кода (линтинг):** Flake8
* **Статический анализатор:** Mypy
* **Модель ветвления:** GitFlow

## 💎 Новые возможности и архитектурные изменения в версии 16.2

1. **Абстрактные классы и интерфейсы (Задание 1 и Доп. задание):**
   * Создан абстрактный базовый класс **`BaseProduct`** (модуль `abc`), гарантирующий наличие методов `__str__` и `__add__` у всех типов товаров в системе. Экземпляр этого класса создать невозможно.
   * Создан абстрактный базовый класс **`BaseGroup`**, который выделяет общие свойства для коллекций и групп товаров. От него наследуются классы `Category` (Категория) и `Order` (Заказ).

2. **Множественное наследование и логирование (PrintMixin) (Задание 2):**
   * Реализован класс-миксин **`PrintMixin`**, который переопределяет метод `__repr__` и автоматически выводит в консоль информацию о типе и параметрах создаваемого объекта в момент вызова конструктора `__init__`.
   * Класс `Product` успешно переведен на множественное наследование `class Product(PrintMixin, BaseProduct)`. Корректно настроена цепочка вызовов `super()` для исключения конфликтов MRO (Method Resolution Order).

3. **Реализация сущности «Заказ» (Order) (Доп. задание к Заданию 3):**
   * Создан новый класс **`Order`**, описывающий покупку одного конкретного товара. Заказ автоматически рассчитывает итоговую стоимость на основе переданной цены продукта и желаемого количества.
   * Метод `add_product()` в классе `Order` заблокирован с вызовом `NotImplementedError`, так как заказ оформляется строго на одну позицию.

## 🧪 Тестирование и покрытие (Code Coverage)

Проект полностью покрыт модульными тестами с использованием `pytest`. Логика сложения, строкового вывода, а также поведение итератора протестированы в изолированном режиме. Общий уровень покрытия функционального кода удовлетворяет критерию наставника (>75%).

* **Запуск тестов:**
  ```
  python -m pytest
  ```

* **Запуск тестов с генерацией отчета о покрытии:**
  ```
  python -m pytest --cov=src
  ```

* **Подробный HTML-отчет (откроется в браузере через папку htmlcov):**
  ```
  python -m pytest --cov=src --cov-report=html
  ```
